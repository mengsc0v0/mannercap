StageCap Data Engine: 细粒度物理约束轨迹合成方案1. 核心动机与创新定位当前开源的机器人轨迹数据集（如 DROID, Open X-Embodiment）存在一个致命缺陷：数据几乎全部是标准的“抓-放”动作，严重缺乏带有方式副词（Manner, 如“缓缓”、“轻轻”、“稳稳”）的长尾操作数据。StageCap 的核心创新在于提出一种可扩展的数据合成范式（Scalable Data Engine）。我们将利用仿真环境底层的绝对控制权，通过代码注入物理约束，主动合成带有细粒度操作方式的高质量轨迹数据集。2. 数据合成 Pipeline (God-Mode Generation)在数据合成阶段，我们将舍弃容易出错的视觉感知，完全利用特权信息（Privileged Info）以保证近乎 100% 的轨迹生成成功率。状态获取： 直接从 RoboSuite 或 Libero 的底层 API 读取所有物体的精确 6D 位姿和几何尺寸。策略生成： 使用目前成功率最高的大语言模型作为核心生成器。指令分发： 每次生成任务时，随机附加 Manner 指令（例如：Prompt = "将红块叠在绿块上，要求：靠近阶段缓缓移动，接触阶段轻轻抓取"）。代码输出与执行： 大模型输出带有具体物
理参数约束的控制脚本，在仿真中静默执行，并录制连续的
动作轨迹（Action Chunk）和对应的细粒度文本标签。3. Manner
约束的具体实现路径（技术重点）要让机器人的轨迹真正体现出“缓
缓”、“轻轻”，我们必须对底层控制 API 进行改造，将语言指令映
射到底层物理参数。以下是具体的实现路径建议：A. 运动学约束：
调整速度与加速度上限 (针对 "缓缓", "快速")摒弃默认的匀速插
值轨迹。在底层 API 中暴露最大速度 (v_max) 和最大加速度 
(a_max) 参数。实现方式： 封装一个新的 
goto_pose_with_profile(target_pose, v_max, a_max)。
逻辑映射： 当提示词要求“缓缓靠近”时，代码模型应在生成的
这一阶段将 v_max 和 a_max 设定为极小值；若要求“快速抬起”，
则设定为较高值。B. 动力学约束：调整末端执行器阻抗刚度 
(针对 "轻轻", "重重")在 OSC (Operational Space Control)
控制器下，机械臂的柔顺程度由刚度矩阵
（Stiffness Matrix, $K_p$）决定。
实现方式： 暴露控制器的位置刚度和姿态刚度参数 
set_impedance_stiffness(kp_pos, kp_ori)。
逻辑映射： 当执行“轻轻叠放”或“轻轻接触”时，
代码模型主动调低目标方向的 $K_p$ 值，
使机械臂表现出极高的柔顺性（遇到碰撞时不会硬抗）；
当执行“牢牢抓紧”时，调高刚度。C. 夹持器力矩控制 
(针对 "虚握", "紧握")不要使用只有 0（开）和 1（关）
的二值夹爪 API。实现方式： 
调用允许设置闭合力矩或指定闭合缝隙的 API，
如 close_gripper(force=0.1) 或 
close_gripper(width=0.02)。
逻辑映射： 对易碎物体或要求“轻轻拿捏”的任务阶段，
代码模型赋予一个较小的 force 参数。D. 轨迹平滑度约束：
Jerk 限制 (针对 "平稳", "颠簸")实现方式： 
对生成的 Waypoints 进行插值采样时，增加或减少控制频率，
或者在轨迹生成算法（如五次多项式插值）中限制 Jerk（加加速度）。
