# Stage-CAP: 方法草稿

## 3. 方法

### 3.1 问题设定与架构概述

本研究聚焦于在仿真环境中自动生成机器人操控轨迹的问题。给定一个由自然语言描述的任务指令 $x$ 和一个模拟器环境 $\mathcal{E}$，我们的目标是自动化地合成一条高保真度的操控轨迹 $\tau = \{(o_t, a_t)\}_{t=1}^T$，该轨迹不仅能成功完成指定任务，且能直接输入到下游的 VLA 模型中进行模仿学习微调。

与传统将长时域轨迹视为单一、不可分割的端到端生成对象的做法不同，我们将长时域操控任务形式化分解为一个带有验证约束的连续阶段序列：

$$\mathcal{P}(x) = \{s_1, s_2, \dots, s_K\}$$

其中 $K$ 表示任务包含的总阶段数，每一个阶段 $s_k$ 均被赋予了显式的语义边界与行为合约。

> 【图1：Stage-CAP 整体架构总览图】

为了构建该阶段序列，系统内置了一个任务层规划器。当接收到新指令 $x$ 时，规划器首先解析其所属操作族，并调用从成功操控语料库中离线蒸馏出的抽象阶段先验来构造一个 TaskPlan。需要明确的是，该规划器并非检索或复制既有的成功代码片段，而是输出一个抽象的阶段状态机。状态机为每个阶段 $s_k$ 定义了严格的结构约束，具体规格见表1。

**表1：阶段状态机要素定义**

| 要素名称 | 形式化定义与作用 |
|---|---|
| `stage_id` | 阶段的唯一语义标识符，定义其在整个操控链中的位置与语义角色（如接近、抓取、运输、释放）。 |
| `target_references` | 显式声明该阶段策略可依赖的目标锚点，如目标物体、目标区域或关节阈值。 |
| `checks` / `success_criteria` | 由一组验证检查项构成，每项包含类型（视觉/几何/混合）及判定阶段完成所需满足的断言；`success_criteria` 以字符串列表形式挂载于各检查项之下。 |
| `repair_hints` | 指导本地修复的启发式偏置说明，防止模型在失败时盲目重复无效动作。 |
| `max_attempts` | 允许该阶段在单次回合内进行本地重试的最大预算上限。 |

在运行时，Stage-CAP 采用"单次回合、物理连续"的闭环执行范式。系统仅在回合启动时对环境调用一次重置操作，此后绝不因为单个阶段的失败而回滚或重置物理环境状态。相反，系统基于当前的实时仿真状态，按阶段动态生成策略代码、执行并验证，通过自更新机制实现高弹性的局部故障恢复。

### 3.2 分阶段策略合成与自更新执行

#### 单阶段代码生成

对于当前待执行的阶段 $s_k$，系统构造一个高度结构化的阶段级提示词，要求大语言模型在给定的语义边界内，仅输出当前阶段的一段可执行 Python 代码，从而将开放式的全局代码合成收缩为受约束的局部规划问题。该提示词聚合了以下多维上下文：

1. **全局状态机拓扑**：提供完整的操控链信息，但限制其控制权，禁止越界调用后续阶段的高风险原语。
2. **阶段合约描述**：注入当前阶段的语义意图、允许调用的只读观测接口与验证条件。
3. **仿真器特权状态快照**：收集当前时间步的紧凑环境状态快照（包括基于 BDDL 的关系诊断、末端位姿、对象位姿及物理接触诊断），作为代码生成的场景定位基准。
4. **历史执行证据与修复上下文**：如果该阶段在当前回合中曾经失败，系统将保留同一阶段此前的执行记录（包括状态、推理逻辑、标准错误输出尾部日志等），显式要求模型依据失败证据进行增量修复，严禁盲目复制通用的专家样本。

#### 阶段执行与证据转换逻辑

代码通过安全执行层后，进入模拟器运行。Stage-CAP 实时捕获标准输出流，并结合环境奖励及 BDDL 诊断逻辑，联合融合成该阶段的验证证据。随后，系统调用阶段决策器，将验证证据映射为以下五类状态转移决策：

- $\text{PROCEED}$：当前阶段满足验证断言，控制器将状态机推向下一阶段 $s_{k+1}$。
- $\text{RETRY\_STAGE}$：阶段内部轻微偏差，在当前代码下继续保持仿真步进重试。
- $\text{REPLAN\_STAGE}$：代码行为不当但物理环境未破坏，在保持当前物理状态不变的前提下，为该阶段重新合成一段新代码。
- $\text{REPLAN\_SUFFIX}$：判定物理操控失败已严重破坏了后续阶段的物理前提（例如在运输过程中物体滑脱），控制器强制将状态机回退到更早的前置阶段（如重新调用抓取阶段），在当前物理状态下重新建立物理前提。
- $\text{FAIL\_TASK}$：出现严重越界或超出最大重试预算，终止当前回合。

这一逻辑构成了基于证据的局部策略修复闭环，每一次重规划都会将前一次的失败证据递增式地编织进下一轮的提示词中。

### 3.3 故障关键帧定位机制

精准定位失败发生的时空边界是实现局部策略修复的关键。Stage-CAP 通过两级联合定位机制，将抽象的失败标签转化为具有丰富语义的具身视觉诊断样本。

> 【图2：两级故障关键帧定位机制示意图】

#### 第一级：在线阶段边界定位

第一层定位发生在当前回合内部的阶段转换边界。每段阶段代码在结束时均会显式报告结构化的 `STAGE_STATUS` JSON。若阶段验证器判定当前阶段未满足完成条件，执行器将在该边界时刻立即截获仿真环境，并同步抓取当前的物理视频帧，保存为原始帧与带有阶段状态标记的标注帧。由于此帧精确对应"验证失败"的临界时刻，且后续的局部重试并不会重置环境，它为当前物理状态下的实时策略修复提供了最直接、上下文完全对齐的视觉证据。

#### 第二级：跨回合关键帧抽取

第二层定位发生在回合整体宣告失败后的后处理阶段，用于为下一轮迭代提炼更强有力的视觉反馈。系统对失败回合的完整视频流与阶段追踪日志进行联合分析，构建关键帧候选集：

- **事件驱动候选**：通过解析日志中各阶段的转换时刻、局部失败断言和最终报错事件，经仿真步数到视频帧的单射映射，将离散的语义事件精确对齐到具体视频帧。
- **运动驱动候选**：对完整视频流进行时空光流分析，筛选出运动强度产生显著梯度的视频帧，以此捕获仅靠阶段边界日志可能遗漏的瞬时动态变化，例如接触状态的突变、抓持物体的微小滑脱以及放置时的碰撞偏移。

系统采用如下优先级准则对上述两类候选进行融合与时间窗口去重：

$$\text{最终关键帧集合} = \text{融合}(\text{最终失败反馈} \succ \text{阶段失败事件} \succ \text{阶段成功事件} \succ \text{运动显著帧})$$

若某个物理操控失败事件在时间轴上与一个高光流运动帧高度重合，两者的空间证据、修复提示与运动得分将被合并归一。最终抽取的关键帧不仅包含图像数据，还显式绑定了触发该状态的 `stage_id`、失败原因描述以及对应的验证检查条件，转化为可直接被大模型消费的具身诊断样本。

### 3.4 双通道故障自适应修复机制

Stage-CAP 并不依赖离线训练独立的诊断模型，而是将阶段级故障定位提取的多维故障证据直接转译为下一次代码生成的结构化上下文，形成文本诊断通道与图像反馈通道的双通道自适应修复闭环。在默认配置下，文本诊断通道作为核心主链路运行，而图像反馈通道可作为选择性增强组件开启。

#### 文本诊断通道

文本通道通过细粒度地区分两类具有截然不同故障机理的失效模式，引导大模型进行针对性修复，避免了盲目的试错：

1. **代码与接口契约失败**：表现为非法 API 调用、语法错误或参数绑定逻辑异常。此类失败被归类为 `needs_repair` 状态，系统将截取标准错误输出的尾部日志，生成聚焦于代码骨架纠错和合规性修正的定向反馈。
2. **物理操控失败**：表现为夹爪未抓稳、搬运途中掉落、合页未达到开合阈值等物理约束违规。此类失败将激活围绕几何空间关系、物理接触状态及目标区域修正的具身策略修复提示。

#### 图像反馈通道

当图像反馈通道开启时，故障定位机制提取的标注关键帧将被动态编码进下一轮代码生成的提示词中。每张图像均叠加了失败时的多维状态元数据，系统同步为其生成压缩版补修指令以实施具身动作约束：

- 若物理失效发生在抓取抬升阶段（`pick_lift`），指令将强制大模型停止盲目重复当前的抓取动作，转而沿候选抓取点索引推进并切换备用抓取策略族。
- 若物理失效发生在运输或释放阶段（`transport` / `release`）且特权状态显示抓持前提已丢失，指令将触发状态机的 `REPLAN_SUFFIX` 转移，提示大模型主动回退到抓取阶段重新建立物理前提，严禁在无物状态下徒劳修补释放代码。

### 3.5 轨迹记录与数据输出规范

当一个回合执行终结后，Stage-CAP 的底层数据引擎将完整记录高频的轨迹步骤。系统以行分隔的 JSON（`jsonl`）格式保存每一个底层时间步的精细状态，包括末端位姿与夹爪状态的联合编码观测（`observation.state`，具体为末端执行器三维位置、轴角姿态与夹爪关节量的 8 维向量）、可审计的底层控制量动作（`action`）、高频时间戳、帧索引、回合索引以及同步的相机图像文件路径。

在空间状态表示上，我们严格采用 LeRobot 风格对末端位姿与夹爪状态进行联合编码，并额外导出候选的动作序列。尽管 Stage-CAP 在运行过程中保存了包含失败尝试的完整物理演练轨迹，但为了保证下游模型进行模仿学习或微调时的策略纯净度，系统的数据转换脚本目前主要筛选并打包由阶段验证器持续审计并宣告完全成功的闭环轨迹，沉淀为高产出的标准 LeRobot 数据集，直接对接下游的微调流水线。
