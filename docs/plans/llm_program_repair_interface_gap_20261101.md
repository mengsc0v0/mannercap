# 任务程序生成与局部修复入口：接口缺口简表（第一步，未写任何 LLM 提示）

依据：`synthesis_v2/task_program.py`、`program_executor.py`、`approach_planner.py`、`language_plan.py`、`llm_interface.py`、`llm_proposal_contract.py`、
`e0_proposers.py`、`attempt_ledger.py`；CaP-X 的 `capx/integrations/base_api.py`、`franka/libero*.py`（LLM 写 Python 调用 API，无本仓库的审计与力带）。

## 一、LLM 现在能调用什么
| 入口 | LLM 的输出 | 谁决定抓取参考 / 路径 / 阶段顺序 |
|---|---|---|
| `language_plan.compile_request` | 句子 -> 对象/阶段/方式绑定（语义） | 配置（`SPECS[task]`、`make_program`） |
| `llm_proposal_contract` | 方式参数（速度、力度边界）候选 | 配置 |
| `e0_proposers` | 零 API 基线，不读仿真结果 | 配置 |
| `TaskProgram.from_dict` | 无人调用；可由 JSON 构造阶段程序 | 实际由 `make_program` 手写 |

## 二、T8 所需动作能否表达 -> 缺口 -> 最小新增
| # | T8 所需 | 现状（已核对） | 缺失 | 最小新增接口 |
|---|---|---|---|---|
| 1 | 完整姿态贯穿全阶段 | 已有：`hand_quat_obj_xyzw` -> 规划器第 5 项 -> 同一 `quat` 用于接近到退出（Step 23） | 只能由 `TaskSpec` 中的参考字段给出，LLM 无法选用；一个物体一个参考 | 参考库：带来源（示范号、闭合步、物体）的参考记录，程序里写 `reference_id`，而不是内联数值 |
| 2 | 对象相对的途经点 / 入口位姿 | 接近 = 起点 -> hover（抓取点上方）-> 世界竖直线下降；不可由程序表达 | 无途经点；下降方向固定为世界竖直 | `grasp.params.via`：对象系途经点列表（位置 + 完整四元数）；下降沿“入口 -> 抓取”的直线，不一定竖直 |
| 3 | 对象相对的短参考片段（含夹爪时序） | 示范只在离线脚本中读取（`s9`/`s22` 抽取），执行器没有片段回放原语 | 缺失。只给抓取位姿会丢失接触建立时序 | 新原语 `replay_segment`：片段 = 对象系位置/姿态序列 + 夹爪时序，按当前物体位姿适配，仍通过伺服执行 |
| 4 | 规划检查与执行使用同一姿态和路径 | 姿态一致（Step 23）；路径不一致：规划只检查 hover 竖直下降，横移只检查两个端点姿态 | 带途经点、带旋转的路径无法被预检 | 规划器改为检查执行器将要走的同一折线，沿线插值旋转；判据与阈值不变 |
| 5 | 超出能力时明确拒绝 | `StageInstance.params` 不做键校验，未知键被静默忽略（执行器按键读取） | 无“能力不支持”返回；LLM 写错或越权参数会静默退回默认动作 | 按原语的参数模式注册表（键、类型、范围）；`validate()` 对未知键返回 `capability_unsupported:{id}:{key}`；执行器拒绝运行 |
| 6 | 失败即停并返回结构化反馈 | 已有：`stage_failure`、`grasp_failure`（Step 23，需开关）、`approach_plan` 候选与间隙、接触审计 | 反馈分散在 `meta`、审计文件里；开关默认关；无统一格式；无“位姿差”“是否抬起/滑移” | `FailureReport`：首个失败阶段、目标与实际位姿差、涉及接触（对象、部位、力、持续步数）、抬起量与滑移、失败的要求编号、可用恢复点；纯由已有记录拼装 |
| 7 | 恢复点 | 已有：按阶段标签的 `StageSnapshot`、`resume`；成本记账 | 按“修改影响范围”选择有效前缀的规则只在方式参数上用过 | 对程序局部修改：由被改实例的位置算出最早受影响阶段，复用其之前的快照（沿用现有 `resume`） |
| 8 | 提案不得改任务、方式、阈值 | 无机制 | 缺少边界 | 提案 = 对阶段实例的补丁；提交前对原始请求、方式要求、验收阈值、接触政策版本的哈希做比对，不一致则拒绝 |
| 9 | 每轮记录与预算 | `attempt_ledger`、`llm_interface` 的调用记录与预算已有 | 未与程序补丁、差异、反馈串联 | 每轮存：输入、输出、程序差异、执行反馈、物理成本、模型成本；固定最多三轮 |

## 三、优先级（不是实现承诺）
先 5、8（让提案可校验、越权可拒绝，改动小，所有任务共用）-> 1、6（参考库与反馈）-> 2、4（途经点与同一路径预检）-> 3（片段回放，最大）。
T8 的当前阻塞（示范张开的手已贴在把手上）能否被“更早的无接触入口 + 保留后续接近与闭合”绕开，只有 2、3、4 到位后才能验证；
是否真正绕开不是已知结果，也可能仍被接触政策拒绝。

## 四、对照设计（第三步，需先定）
共用同一执行器、参考集合、轮数与成本预算：确定性选择/修复（固定顺序遍历参考与入口）对 LLM 选择/修复（同一份反馈）。
报告任务成功、联合合格率、修复成功、物理成本、模型调用成本；失败案例全部保留。
