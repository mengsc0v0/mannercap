# MannerCAP 轨迹合成实施与交付方案

版本：v2，2026 年 9 月 15 日。
适用对象：项目负责人、轨迹生成、仿真控制、数据及评测成员。
状态：拟实施与验收合同；不是已完成方法或实验结果。
版本关系：以本文替代 v1 的任务优先级、方法设计、实验矩阵和排期；v1 保留，不覆盖。本文可独立用于分工与验收。

## 1 本版的项目目标

核心交付是一种面向操作方式学习的轨迹合成方法：给定任务、语言要求、阶段结构和允许使用的物体属性，生成阶段可控、上下文合理、经过物理验证的机器人示范，同时输出可靠的语言与阶段标注。

下游 VLA 用来检验这些数据是否具有学习价值。第一轮固定学生模型、动作接口和训练流程，优先改变数据来源，不同时把新模型结构、新损失和新合成方法作为主变量。

本项目需要回答两个相互关联的问题：一是合成方法能否在有限预算下产生更多合格、有效覆盖不同条件的示范；二是在公平训练条件下，这些示范能否改善学生的显式方式遵循、阶段方式绑定和上下文方式选择。两者都需实测，不能由上游教师成功直接推断学生已经学会。

建议投入为 4 个技术负责人角色，项目负责人统筹，另配必要的标注支持。暂按 10—12 周组织工作，第 4 周以前完成小数据学习检查；具体工期、规模和预算须根据实际设备与人员在 Gate 0、Gate 2 两次复核。本版没有提前承诺论文效果或投稿级别。

### 与 v1 的关键变化

| 项目 | v1 的重点 | v2 的执行要求 |
|---|---|---|

| 主要比较 | 四种控制系统的运行效果 | 合成方法的合格率、可控性、覆盖、成本及学习价值 |
| 强基线 | 固定、规则、显式解析 | 增加阶段化采样加相同筛选、上下文规则生成器 |
| 数据工作 | 支撑后期训练 | 核心交付，增加请求覆盖、配对、去重和生成台账 |

## 2 首轮范围和结论边界

| 维度 | 首轮必须支持 | 后置或单列的内容 |
|---|---|---|
| 环境 | 单臂仿真，固定环境与控制器版本 | 真机、跨硬件迁移 |
| 任务 | Lift、Stack，以及经验证的接触任务，优先 Wipe | 任意技能发现、双臂、流体 |
| 方式 | 无方式词、慢、快、轻柔、两类阶段组合指令 | 无限自然语言表达与全部控制维度 |
| 阶段 | 有物理事件依据的阶段实例与作用范围 | 首轮不强制另训视觉阶段识别器 |
| 对象 | 每任务拟设 4 类可校准物理配置 | 没有感知线索的隐藏属性推断 |
| 控制 | 同一执行器、控制参数域和安全层 | 各组不同隐藏控制规则 |
| 学生 | 一个固定、现有可用的 VLA 起点与学习流程 | 新骨干、新辅助损失作为主要贡献 |

阶段组合指令拟包括“快速接近、缓慢接触”和“缓慢接近、快速搬运”，最终用语及任务适用性由校准决定。不适用或存在冲突的单元在正式运行前统一移入限制测试集，不按某个方法的失败结果删除。

第 1 周确认第三任务是否有可靠的接触量和任务结果定义。若 Wipe 不具备条件，可由负责人批准替代任务；若最后只有 Lift/Stack，结论必须收缩到抓放任务，不能声称一般接触操作均已验证。仿真无破损或清洁模型时，必须明确代理物理阈值和代理任务结果，不能把代理量写成真实损伤或清洁效果。

教师可以使用当前仿真对象状态、阶段事件和属性。该设定属于特权信息辅助的合成，不是视觉推理能力证明。离线标签可以利用未来帧确认事件，但教师闭环控制不能访问未来状态；学生输入中必须隔离离线未来信息与未声明的特权状态。学生的隐式方式测试应提供可观测或明确告知的属性线索。

## 3 项目负责人最终应收到什么

最终交付不以轨迹总数或成功视频数签收，而是六个互相引用的版本包：

1. 合成器源码、依赖、配置、命令入口和版本标识。
2. 阶段、对象、方式约束与动作接口规范。
3. 含全部请求、候选、失败、重试和成本的生成台账。
4. 原始轨迹、阶段标注、配对关系、去重记录、数据卡与训练导出。
5. 独立合成评测、强基线、消融和成本覆盖报告。
6. 固定 VLA 的数据来源对照、模型、闭环结果和可复算发布包。

核心证据按以下条目验收：

| 编号 | 拟验证能力 | 必须提交的证据 |
|---|---|---|
| R1 | 显式方式可控合成 | 同初态、只换方式词的实际轨迹与物理差值 |
| R2 | 阶段方式绑定 | 指定阶段达标与非目标阶段串扰，含阶段真值质量 |
| R3 | 上下文合理合成 | 中性指令、属性干预与独立可接受物理区间 |
| R4 | 物理合格 | 任务、方式、安全分别判定，欠作用和过作用均检查 |
| R5 | 有效且高效的数据生产 | 全尝试分母、有效覆盖、去重后产量、成本向量 |
| R6 | 方法增量可归因 | 同执行器和信息条件的强基线及逐项消融 |
| R7 | 学生确实受益 | 固定学习流程，同数据量与同采集预算的闭环比较 |
| R8 | 泛化与复现 | 分离的生成器测试与学生测试、未见组合、版本化复算 |

R1—R6 主要评价合成器；R7—R8 中的学生结果另行评价。合成器标签正确，不等于学生已经学习成功。任一研究假设不成立时，允许签收真实执行与负结果，不允许签收未达到的效果。

## 4 人员分工

| 角色 | 最终责任 | 主要交付 | 交叉评审 |
|---|---|---|---|
| 项目负责人 | 冻结主张、范围、预算、主比较和变更 | 立项基线、放行记录、最终结论 | 全组 |
| A 仿真与执行 | 真实推进、测力、阶段事件、动作回放、统一执行器 | 校准包、执行器、轨迹记录 | B、D |
| B 独立评测 | 阈值、最终审计、测试封存、统计与预算口径 | 评测器、金标规范、主结果表 | 项目负责人 |
| C 合成方法 | 条件编排、阶段候选计划、合成基线与受限重采样 | 合成器、方法规格、生成日志 | A、B |
| D 数据与学习验证 | 数据工厂、去重、配对导出、固定 VLA 验证 | 数据版本、回放报告、学生结果 | A、B |
| 标注支持 | 按规范独立标注与复核 | 原始标注、分歧及仲裁记录 | B |

C 的主责从“在线智能控制系统”改为“轨迹合成方法”；D 不等到后期才介入，第 1 周即检查学生动作能力。B 不能由方法作者单独兼任并自行更改测试阈值；人手不足时至少安排非作者复核，披露独立性限制。

每个工作包指定一名最终负责人。每周例会只汇报交付证据、依赖、质量和预算，不以代码行数或演示次数报完成度。逾期必须说明阻塞项和对后续关口的影响。

## 5 拟实施的合成方法

本节是待实现的算法规格，不表示仓库已有这些模块。首版在现有任务与阶段执行模板上实现，不同时生成全新技能代码或开发复杂故障恢复器。

### 5.1 合成请求

一个请求定义一个目标示范，包含任务、完整初态、目标对象、物理配置、原始语言、阶段作用范围、允许控制通道、请求所属数据划分和预算。一个请求最多发布一条示范，多个候选与重试均属于该请求。

在运行之前生成 `request_manifest.jsonl`，确定任务—配置—方式—初态配额和配对关系。各方法接收相同请求、可用属性和预算上限。因生成困难没有完成的请求也必须留在台账中，不能只交付已成功的请求列表。

### 5.2 生成模块

| 模块 | 输入 | 输出与职责 |
|---|---|---|
| 请求编排 | 冻结的任务、对象、方式与组合清单 | 合成请求、配额、pair_id、split；避免只生成容易条件 |
| 上下文候选计划 | 任务、语言、阶段实例、教师可用属性、公开控制域 | 分阶段候选速度和可表达的接触控制计划 |
| 执行与记录 | 候选计划、完整初态 | 真实闭环轨迹、事件、实际参数、安全干预与资源消耗 |
| 生成期验证 | 轨迹、公开生成规范 | 通过、失败或 unknown 及结构化原因 |
| 接受与重采样 | 验证结果、剩余预算、重复检查 | 发布候选、重新提案或终止；原请求不变 |
| 标注与导出 | 已接受轨迹及事件 | 实际行为一致的标签、完整轨迹与训练窗口 |

所有方法共享执行器、记录器和安全层。生成期验证器可用于筛选；最终评测由 B 管理，见第 9 节。首版共同使用有上限的接受—重采样协议，不把无限重试当方法能力。

不同方式的轨迹原则上必须通过相应控制计划重新执行。只修改时间戳、离线拉伸轨迹或替换语言标签，不能自动算作新的物理合格示范；若使用此类增强，需要重新验证控制器回放、接触行为和标签一致性，并单独报告。

### 5.3 首版上下文计划的具体实现

默认复用现有语言解析调用方式，将输入从描述字符串扩展为结构化任务、阶段作用范围和物体属性；输出由单一全局参数扩展为阶段计划。模型只能在声明的控制通道与范围内提案，不允许任意执行模型返回的代码。

C 必须交付每个输出字段的定义、单位、对应控制通道、合法域和失败处理。候选至少明确 `stage_instance_id`、对象、速度控制量、适用时间/事件范围；接触力或阻抗字段只有在 A、D 证明执行与学生动作接口支持时才启用。

模型可获得公开的任务物理先验与生成约束，但不能看到最终测试单元的封存答案。上下文规则基线获得同等先验，不能将同一先验只提供给本方法后声称模型更会推断。

原始语言的独立要求、模型预测计划、实际执行计划与实测行为分别保存。模型输出的目标区间不是最终评测真值；不能让模型自己定义容易满足的要求后自行通过。

### 5.4 重采样与失败处理

首轮建议每请求最多 3 次候选提案，该值由 Gate 2 冻结。提案解析失败、非法参数、执行失败、验证失败和重复候选都消耗尝试编号；实际资源按发生量记录。任何方法都不能在未计费的内部循环中额外试候选。

默认首版失败后在同一原始请求下产生新候选，保持共同重试上限；是否向提案器提供上一轮失败原因必须成为显式配置。反馈修正不是首轮必需创新点。若加入它，必须与独立重采样在同预算下消融，且不能悄悄放宽物理要求、改变目标对象或改成更容易的指令。

运行时找到第一个通过生成验证且满足既定去重规则的候选即可发布。若预算耗尽，输出失败状态。最终审计失败的正式测试输出不得回流合成器继续修到通过；否则已消费测试信息，必须另行封版。

失败轨迹全部保留，不删除中间动作后拼成成功轨迹。经验证的真实行为重标注可以作为独立数据操作，但不能算原请求已满足，也不能将失败回合自动变成原指令正例。

### 5.5 配对和覆盖设计

配对至少包含三个类型：相同初态只改修饰词；相同中性语言只改物理属性；相同任务与方式只改作用阶段。属性干预保持几何与其他因素一致，但完整物理状态哈希会变化，应保存干预字段及共同几何标识。

配对成员不能跨训练和测试。只完成一侧的配对保留为不完整配对，不纳入完整配对方向统计，但其失败计入请求产率和覆盖分母。完整配对的额外采集成本应单列，不能只报告成功对。

覆盖按预注册的任务—阶段—方式—属性单元统计，并结合独立初态数及实际行为差异。更换语言措辞、时间戳或随机编号不自动增加物理覆盖。

### 5.6 C 必须提交的可复现方法说明

在正式扩量前提交 `synthesis_method_spec.md`：请求如何选取、候选怎样提出、物理先验来自哪里、如何处理阶段作用域、何时停止、是否利用反馈、去重如何影响接受，以及各模块的消融开关。

流程各步骤可能建立在现有方法上。必须明确拟验证的增量在哪里，不能把“计划—执行—筛选”流水线本身包装为已证明创新。若收益只来自更多尝试或更宽松筛选，报告应承认这一点。

## 6 工作包与验收合同

以下文件与入口是拟交付项，不表示已经存在。内部目录可由 A、C 协商，但对外接口和验收语义必须一致。

### WP0 冻结基线与运行资源

负责人 A，B、D 评审；启动后 3 个工作日交付。

交付 `baseline_inventory.md`、环境锁定文件、代码提交或归档哈希、两任务端到端运行记录、初步吞吐/存储/API 成本表、含负责人和依赖的任务台账。非 Git 目录也要有可核验源码版本，旧结果与旧模型只读保留。

验收：指定实验机能执行一条 Lift 和一条 Stack，并离线重算结果；不能只提交 mock 或编译结果。模型服务不可用、依赖缺失、并发限制和费用约束必须进入资源表。第 4 周再用实际新数据和学生训练修正预算。

### WP1 可信记录与统一执行器

负责人 A，B、D 评审；第 1 周主体完成，第 2 周校准签收。

交付轨迹 schema、实际仿真推进位置的记录器、阶段事件、完整初态恢复、对象级力校准、至少 12 条校准/异常样例、自动质量检查和统一执行器版本。

必查：控制指令与实测值分开，物理子步与控制步分开，力与力矩分开，夹持力与施加给环境的力分开。未经校准的 `cfrc_norm`、kp 或夹爪开度不能改名为真实抓力；混合 N 与 N·m 的六维向量不能直接求范数当作力。

验收：无接触和受控接触可区分，受控载荷变化有合理响应，采样频率和误差可查；真实接触测试仍全程恒定力时退回。实际动作时间轴递增，控制标记独立存储；缺采、reset 和失效不填零冒充合规。语言配对能恢复相同初态及控制器状态。

### WP2 独立物理规范与最终评测

负责人 B，A 协作；第 1—2 周交付，第 4 周冻结正式协议。

交付 `constraint_registry.yaml`、指标与安全规范、生成期验证器、最终审计入口、失败分类、手算样例和反例测试。公开规范与封存测试配置分开管理。

必须修复原约束被裁剪后置空仍通过、全无约束自动通过、单帧达标覆盖整阶段、跨时间缺口求导、缺数据变通过等问题。至少覆盖 12 类自动反例：裁剪、无日志、缺阶段、传感失效、瞬间达标、持续低于下界、安全越界、重复时间、采样缺口、单位错误、错误阶段生效、任务失败但方式通过。

验收：同一轨迹在任意方法名下得到相同最终结果；阈值来自独立校准而非方法表现。unknown、原要求未满足和执行异常分别记录。任务失败、IK 失败或超时不能自动命名为物理不可行。

### WP3 任务与请求空间

负责人 C，A 提供任务适配，B 签收；第 2 周交付。

交付三任务模板、阶段本体、对象属性来源、控制参数合法域、可行性校准、请求清单与配对 schema、数据划分规范。

阶段模板采用可执行程序区间与物理事件共同定义，不需要先另训视觉识别器。每个阶段实例有进入/结束条件和对象角色。对象位姿或“夹爪闭合”不能单独充当抓稳真值。

验收：每任务有成功、欠作用和过作用案例；每个属性有来源和单位。请求空间、不可行/不适用单元及留出组合事先登记。所有可比生成器获得相同任务模板、可用属性、公开先验和控制域。

### WP4 阶段可控合成器及强基线

负责人 C，A 集成，B 评审；第 3—4 周交付。

交付本方案第 5 节的完整模块、方法规格、统一生成入口、五个上游方法配置、共同预算执行器、失败台账和消融开关。默认以现有语言解析器扩展为阶段计划，不另立新大模型训练任务。

验收：相同请求能由各方法运行；限定阶段变化可被实测；所有候选、调用、执行、安全接管和重试均可追踪。生成器不能读取封存测试结果。参数裁剪不修改原始目标。正式扩量前必须由 A、B 复查方法差异是否只在声明的模块。

### WP5 合成质量与效率实验

负责人 B，C、A 运行；第 4 周预实验，第 5—6 周正式比较。

交付正式注册表、请求和尝试台账、最终审计结果、成本/覆盖/配对指标、所有方法与消融的结构化结果、失败诊断与统计入口。

验收：能够从原始台账重算每个分母、每次重试和每条发布数据的来源；同时报告筛选前、筛选后和最终审计质量。方法因覆盖不足、空输出或生成错误不准从比较中消失。无收益也要交出完整负结果，不能事后改变测试范围。

### WP6 数据工厂与学习预检

负责人 D，A、B 评审；第 1 周开始接口核对，第 3—4 周必须完成预检，第 5—6 周形成正式数据版本。

交付数据卡、生成 lineage、配对和去重记录、独立金标、阶段质量报告、Atomic-LA/Full-VLA 导出、至少 30 条导出—导入—学生控制器回放，以及 32—64 条样本的小数据学习检查。

建议金标启动集 60 条，跨任务、方式与成败，其中至少 20 条双人独立标注。标注员不看模型预测答案，允许不确定边界并留仲裁记录。原子引擎证据等级不是准确率；切分测试通过不是训练数据已经可用。

验收：源轨迹不可变，分段完整不重叠；窗口不跨 reset、缺口和非法 padding；先划分回合、对象和组合，再切窗口。动作坐标、单位、四元数、夹爪符号与时刻对应全部核对。回放若存在系统性偏差，停止扩量；小样本无法学习时先诊断数据与接口，不排长训练。

### WP7 固定 VLA 的数据价值验证

负责人 D，B 管理评测；第 7—10 周主体实施，第 11—12 周完成必要复核。

交付固定起点权重、动作接口、训练配置、三个主要数据来源、同数据量和同采集预算两种比较、各主设置至少 3 个训练种子、闭环结果、输入泄漏审计和模型检查点。

阶段辅助损失、新训练策略或新动作头不作为首轮主变量。若接触控制必须扩展学生接口，应先验证教师动作可实现性，再让所有数据来源共用同一接口；相应重估工期。

验收：主比较中仅数据来源及预注册的数据数量差异改变；训练步骤、有效监督量口径、采样和选模规则清楚。验证集选检查点，测试集不参与调参。教师合格率不能代替学生闭环结果，离线 loss 不能代替方式能力。主结果报告全部训练种子。

### WP8 封版与移交

负责人 B 汇总，A、C、D 分别交付，项目负责人签收。

交付源码与环境、请求与数据版本、模型、重算命令、R1—R8 证据索引、成本表、失败与限制说明。发布包包含普通成功、方式不合规、任务失败、安全违规、unknown 和重试耗尽等代表样例。

验收：由非主流程作者在声明支持的环境中复算一张合成主表和一张学生主表，随机抽查 request_id 可追到全部候选及原始轨迹。外部模型不能完全离线复现时保存请求/响应与离线复算路径，绝不包含密钥。

## 7 接口与数据合同

| 层级 | 必需字段 | 语义要求 |
|---|---|---|
| 请求 | request_id、task、scene_id、split、pair_id、原始语言、scope、预算 | 请求在生成前登记，失败不删除 |
| 属性 | object_id、值、单位、来源、教师/学生可用性 | 真值、估计、语言告知不能混写 |
| 提案 | attempt_id、parent_request_id、候选阶段计划、提案来源、调用记录 | 解析失败也有 attempt；内部候选不得隐形 |
| 约束 | requested_constraints、predicted_plan、executed_plan、修改原因 | 三层不可互相覆盖，实测另存 |
| 转移 | observation_t、action_t、observation_t_plus_1、实际 dt | 动作对应正确的状态转移 |
| 视觉观测 | RGB、camera_id、capture_timestamp、相机参数与预处理版本 | 学生所需相机必须记录，禁止错位或重复旋转；图像缺失单列 |
| 物理记录 | 末端/关节、夹爪指令与实测、对象接触力、事件、传感有效性 | 明确对象、单位、坐标系与采样频率 |
| 状态与版本 | 初态/控制器快照、环境与代码哈希、模型版本、各类 seed | seed 不代替完整初态；训练与评测 seed 分开 |
| 质量 | 生成验证、最终审计、阶段来源、不确定区间、重复标识 | 最终通过不由生成器自行修改 |
| 资源 | 仿真子步、调用/token、CPU/GPU 时间、墙钟、存储、重试 | 分方法记录，初始标定和运行成本可分摊追踪 |
| 导出 | trajectory_id、source_attempt_id、窗口索引、标签版本、动作 schema | 每个训练窗口可回到完整原始回合 |

动作 schema 必须写明每一维、坐标系、绝对/增量形式、单位、归一化、夹爪符号、频率、预测窗口与实际执行步数。教师仅能通过隐藏 kp 改变的行为，如果学生无相应动作通道或固定控制器不能复现，不得假定行为克隆会自动获得。

标签以实测行为与验证为准。原始请求保留，重标注生成新标签版本；不同语言标签的同一物理轨迹必须共享 lineage，并在划分及去重中视为关联样本。

## 8 必做基线和消融

### 8.1 五个上游方法

| 方法编号 | 方法 | 所隔离的问题 |
|---|---|---|
| G0 | 固定脚本和固定执行参数，使用共同验证与预算协议 | 默认轨迹能覆盖多少要求，作为参考下界 |
| G1 | 全局控制参数随机采样，加共同验证 | 普通参数多样化能产生多少合格数据 |
| G2 | 按阶段采样候选，加相同物理筛选 | 排除“阶段化随机尝试加筛选就足够”的解释 |
| G3 | 利用同样属性和先验的人工上下文规则生成，加共同筛选 | 强工程基线，检查模型提案的实际增量 |
| M | 本方案上下文阶段候选计划与合成流程 | 拟议方法 |

共同条件：相同请求空间、完整初态、执行器、合法控制域、安全限制、信息访问权限、筛选规范和停止规则。G2/G3 必须用开发集合理调优并冻结，不能刻意选择很差的采样区间或弱规则。G2 可以根据相同的显式语言和阶段作用域限定候选域，不得故意让其在明显违反要求的整个参数空间盲采样。

G0/G1 为参考，核心判断是 M 相对 G2/G3 的质量、覆盖与成本。若 G3 更好，不能将“采用大模型”本身写作优势；应如实评价方法的适用性与贡献范围。

### 8.2 最小机制消融

| 消融 | 改变内容 | 必须保持 |
|---|---|---|
| 无阶段局部控制 | 将计划限制为全局控制，不能逐阶段改变 | 请求、执行器、预算与最终评价 |
| 无上下文属性 | 提案器不读取物体属性，保留任务与语言 | 其他信息、调用预算与测试分布 |
| 无生成期方式筛选 | 不用方式判定筛候选，但保留硬安全保护 | 最终审计仍完整，不能关闭测量后声称通过 |
| 无配对编排 | 独立采集，尽量匹配任务/属性/方式边际分布 | 数量、预算与学生训练流程 |
| 无失败反馈 可选 | 独立重采样而非使用上一轮诊断提案 | 相同候选数与资源上限 |

若实际训练过程只是逐条行为克隆，不额外使用 pair_id，那么配对关系本身不是新的训练信号。无配对消融检验的是采集分布及覆盖结构；不能将效果归因于未实现的对比学习或因果损失。

显式词替换、中性语言属性干预和阶段作用域替换必须保留，分别在教师输出和学生行为上报告。标签打乱仅作机制诊断，不能用一项打乱结果证明完整物理因果模型。

## 9 物理验证和独立性

### 9.1 生成期验证与最终审计

生成期验证器是方法的一部分，可提供接受/拒绝反馈。最终审计由 B 管理，使用冻结指标、未见请求以及独立校准和抽查证据，合成器不读取其逐回合结果进行正式测试修正。

独立性不是必须复制两套不同公式；同一物理量定义可以共用实现。关键是阈值来源、测试信息隔离、测量正确性和非作者复核。既要检验生成期接受的样本是否真的合格，也要抽查被拒样本，避免筛选器误杀困难但有效的条件。

推荐在封存测试中加入校准允许范围内的未见对象/初态及预注册扰动，检查是否只拟合公开模板。不能在看完方法结果后再改变扰动或阈值。

### 9.2 物理与阶段指标

任务成功、阶段方式合规、安全状态使用 pass、fail、unknown。单回合 JPR 事件为 TaskPass AND MannerPass AND NoSafetyViolation；任一明确 fail 则联合失败，全部 pass 才通过，其余 unknown。这里的安全是没有观测到已定义违规，不代表现实绝对安全。

必须记录速度上下界、适用接触阶段的力上下界、超限持续时间、接触冲量、观测峰值和阶段作用范围。力冲量在连续有效区间内按实际 dt 积分，单位 N·s；jerk 按真实时间求导，不跨 reset、缺采和阶段不连续片段。力下界只对需要作用力的阶段生效，自由运动不要求有力。

软方式容忍与硬安全规则分开。top 5% 均值、滤波后峰值等只能作补充，不能替代原始观测安全峰值。任何去抖、阈值或容忍时长必须在正式评测前冻结，并报告测量分辨率。

阶段方式一致性同时报告目标阶段效果和非目标阶段串扰。定向差异必须大于校准得到的最小可分辨变化；只在双方成功样本里算的条件指标应单列，不能掩盖任务失败或不完整配对。

## 10 合成主指标和分母

统一记号：N 是预注册的合成请求数；A 是实际候选提案次数，含解析失败等未执行提案；P 是真实执行的轨迹数；R 是发布轨迹数；V 是发布后经最终审计确认合格的数量；V_u 是按冻结规则去重后的合格数量。一个请求最多发布一条，所以 R 不大于 N。

| 指标 | 定义或统计口径 | 防止的误读 |
|---|---|---|
| 执行轨迹 JPR | 在 P 条实际执行轨迹上逐条最终评价 | 不等于整个生成流程的产率 |
| 请求合格产率 | V / N | 不允许丢掉解析失败、预算耗尽、空输出请求 |
| 去重合格产率 | V_u / N | 防止重复轨迹充数 |
| 发布质量 | V / R；R 为 0 时记不可计算，同时报告零产量 | 不能只靠少量精选样本掩盖低产量 |
| 尝试合格率 | 最终确认合格的候选轨迹数 / A | 重试和不执行的错误候选仍消耗分母 |
| 完整配对产率 | 两侧均最终合格的配对数 / 计划配对数 | 不完整配对不得悄悄排除 |
| 有效覆盖 | 达到最低独立初态数和物理质量要求的单元数 / 目标单元数 | 文本改写和更多帧不自动增加覆盖 |
| 标签一致性 | 独立审计的阶段、对象、语言与实测行为一致情况 | 标签透传不等于标签正确 |
| 单位有效数据成本 | 总资源 / V_u，并报告原始资源向量 | 失败、重试、筛选与重复均计入成本 |

成本向量至少包含总物理子步、模型调用/token、CPU/GPU 时间、墙钟、存储。单位成本在 V_u 为零时标为不可用或无有限产出，不能填零表示便宜。首次任务标定、人工规则编写和运行成本分开披露；若主张可扩展性，不能完全隐藏新任务的人工适配成本。

unknown 不能算合格。对 N 个请求，若 U_R 是已发布但最终资格仍不确定的请求数，报告保守产率 V/N 及缺失状态边界 [V/N, (V+U_R)/N]；未产生输出的请求不是“可能成功”的 unknown。该边界与统计置信区间分开。

去重先精确校验 lineage/hash，再按预注册的几何路径与物理行为特征检查近重复。不能只按末端路径删除快/慢等真正不同的方式轨迹；至少联合时序速度、接触行为、对象配置和阶段作用域，由 B、D 在开发集抽查阈值。每个丢弃项保留理由与关联轨迹。

## 11 实验矩阵和正式规模

以下规模用于排资源，全部是建议而非已跑结果。在 Gate 2 根据吞吐、预实验方差和预算冻结；不以当前数字代替样本量判断。

### E0 开发预实验

建议 `3 任务 × 2 物理配置 × 4 指令类 × 3 初态 × 5 方法 = 360 请求`。每请求最多 3 次提案，最多 1080 次提案，其中实际执行次数不超过提案数。先分批排除接口和测量错误，开发结果不并入正式测试。

此阶段同步做完整动作回放及 32—64 样本学习检查。第三任务暂未校准时可以先用两任务调试，但正式接触结论仍需补齐。

### E1 同请求和同尝试上限的合成比较

建议 `3 任务 × 4 物理配置 × 6 指令类 × 10 初态 × 5 方法 = 3600 请求`。最多 10800 次提案；方法在首次接受后停止，不要求所有请求都用满 3 次。

各方法共享 720 个基础请求条件，方法运行顺序随机化，模型/API 随机性和缓存策略事先固定。若模型随机性较大，对冻结子集增加独立重复并单列预算；10 个初态不保证足够统计功效。不可行单元统一移出后，以正式 manifest 数量为准。

这项实验比较有限尝试下的可控性、产率和成本，不强行假定每个方法实际花费相同。生成器正式测试请求及输出不能进入学生训练。

### E2 同采集预算的数据生产比较

主比较使用 G2、G3、M，在与 E1 分离的训练请求池生成数据。预注册主要预算为相同仿真物理子步上限，并设置相同的请求/候选上限及适用的计算/API 资源上限；所有资源向量同时报告。

物理子步相同不等于货币或总计算成本相同。若主张“更便宜”，还必须比较完整成本；不能忽略 M 的模型调用开销。预算耗尽必须停止，不能为补齐漂亮结果继续采集。

分别报告预算下的去重合格数、分布覆盖、完整配对数和学生学习结果。预算数值由预实验确定，不在无吞吐依据时虚构固定金额。

### E3 合成模块消融

优先比较无阶段局部控制、无上下文、无生成期方式筛选三个设置。配对编排和失败反馈根据实际方法启用情况增加。每项至少保留同条件请求、相同执行与资源限制，并对全部结果运行最终审计。

先在冻结诊断子集运行；只有预注册为主证据的消融扩至正式规模。不能运行很多消融后只报告有利项。

### E4 学生学习价值

主数据来源为 G2、G3、M；固定 VLA 和训练协议，做同数据量与同采集预算两种设置，详见第 13 节。旧原始模型可作参考，但不能替代同预算、同接口的数据来源对照。

### 统计与报告

生成器结果按请求/初态进行配对比较和分层统计，不能把候选重试或逐帧值视为独立样本。下游训练种子与评测初态分别报告，按实际独立单元计算区间；3 个训练种子仍不足以精确刻画所有训练方差，应承认限制。

预注册主指标、最强可比基线、任务宏平均、关键子组及多重比较处理。重点给差值和 95% 区间，不只给单个 p 值。样本不足时报告不确定性，不事后删困难子组。

## 12 数据划分与分阶段生产

至少区分四类数据用途：开发/校准集、生成器封存测试集、学生训练/验证集、学生封存测试集。先分任务实例、对象、模板族与留出组合，再生成请求及窗口。训练归一化、阈值调试和检查点选择不得使用学生测试集。

生成器和学生的留出机制分别登记：生成器评估新的请求与上下文能否合成；学生评估训练中没有的对象、语言或阶段方式组合能否执行。不能把同一个“未见”一词用于两种不同对象而不说明。

| 数据档位 | 建议规模 | 用途和放行条件 |
|---|---|---|
| D0 | 约 60 条质量启动轨迹 | 金标、字段质量和回放；不能作为最终性能证据 |
| D1 | 每主数据来源约 250—1000 条合格示范 | 学习预实验、吞吐和分布检查；先证明数据可学 |
| D2 | 每主数据来源目标约 3000 条，按预算调整 | 正式同数据量比较；须满足覆盖与去重标准 |
| 扩展 | 1000—5000 或更大规模的曲线点 | 非默认无上限扩量，D1 有信号且资源批准后执行 |

以上单位均为完整 episode，不是片段数或帧数。每来源成本分别计数；训练一组并不意味着可将其数据数量写成全组数量。

同数据量比较应先冻结任务/属性/指令的分层配额及抽样规则，尽量匹配来源分布；不得按学生测试表现挑选教师数据。某个基线在成本上限内无法达到数量或某配额时，应报告这一限制，并使用所有来源可达到的共同规模做质量比较。不能临时给本方法更容易的条件。

同采集预算比较保留自然产量和覆盖差异，它反映整个合成流程的效益，不应被解释为纯粹单样本质量差异。配对和 lineage 的跨划分泄漏检查是发布前强制项。

## 13 下游学习合同

固定学生模型、起始权重、动作头、控制器、部署输入、优化器、训练步数、批量、采样规则、增强、归一化口径和选模规则。实际动作长度不同导致有效监督量不同，应记录并匹配或明确说明，不能只匹配 epoch 数。

第一轮统一采用可用的既有学习流程。原子标签主要用于数据质量、作用域与诊断；若把阶段标签额外作为损失或输入，则是另一个实验变量，必须所有来源一致，或单独研究，不能混入数据来源主比较。

| 设置 | 数据控制 | 所回答的问题 |
|---|---|---|
| L-size | G2、G3、M 使用同样数量、按冻结配额抽取的合格数据 | 每份数据的学习价值是否更好 |
| L-budget | G2、G3、M 使用同采集预算实际得到的数据，学习预算固定 | 同样采集投入是否带来更好的最终学生 |

每设置每来源至少 3 个训练种子，即 `2 设置 × 3 来源 × 3 种子 = 18 次正式训练`。两设置的数据和配置完全一致时可以复用同一训练结果，但必须记录复用关系，不能当作独立重复。数据规模曲线和探索训练另计，不藏在这 18 次中。

若沿用 `3 任务 × 4 配置 × 6 指令 × 10 初态 = 720 回合` 的学生核心评测，每个正式模型评 720 回合，总量为 12960 回合，不含挑战集和预实验。此处是预算上限规划中的基准规模，并非必须无条件跑满；在 Gate 2 可根据统计功效和资源调整并冻结，不能事后只保留有利结果。

学生主指标为 JPR 及任务、方式、安全分项；同时报告显式方向一致性、阶段串扰、中性语言属性响应、未见组合与失败类型。JPR 在所有应计入回合上统计，unknown 不算成功，并报告覆盖和缺失状态边界。

闭环学习检查必须前置：小数据过拟合仅证明训练通路可能正确，不证明泛化；导出回放仅证明动作可实现，不证明模型已能预测。二者均通过后才批准长训练。固定控制器或外置模块贡献单列，不能归因给学生。

## 14 质量门槛与科研效果分开签收

以下数值为待批准的工程目标，不是已有结果或领域标准。在 Gate 1/Gate 2 根据校准与任务难度冻结，不能看到正式结果后修改。

| 类型 | 建议验收条件 | 不通过的处理 |
|---|---|---|
| 台账完整性 | 请求与候选状态 100% 可追溯，成本包含全部尝试 | 退回合成实验报告 |
| 动作接口 | 所有通道、单位、时刻明确；30 条回放无系统性偏差 | 停止扩量和长训练 |
| 物理测量 | 校准通过；正式审计 unknown 建议不超过 1% | 先修测量或缩小可测范围 |
| 阶段质量 | 独立金标下，±2 控制周期边界 F1 和宏阶段 F1 均以 0.85 为启动目标 | 修标签并报告覆盖与分任务误差 |
| 发布质量 | 最终审计合格率建议至少 95%，硬安全违规目标为零 | 退回数据版本，不能只删除失败后重算 |
| 覆盖 | 每个声明支持单元达到冻结的独立初态和质量配额 | 缩小支持范围或补采；保留未完成清单 |
| 科研效果 | 相对 G2/G3 在预注册的质量、覆盖或成本维度有可解释优势 | 如实交负结果，不能仅换名称宣称创新 |
| 学习价值 | 固定学习条件下主指标差值与不确定性支持结论 | 缩小学习主张，不以最佳单种子代替 |

发布质量高不代表生产效率高，因此必须与请求产率、覆盖和成本一起看。零观测违规不等于绝对安全，须报告样本量与不确定性。也不要求在所有指标上同时最好；可以报告明确的质量—成本权衡，但不得隐藏劣势。

## 15 排期和放行关口

放行关口记为 Gate 0—Gate 5，与生成方法编号 G0—G3 区分。

| 时间 | 必须交付 | 放行决定 |
|---|---|---|
| 第 1—3 天 Gate 0 | 角色、代码/环境基线、两任务运行、初步资源表、动作能力清单 | 环境真实可运行，接口有负责人 |
| 第 1—2 周 Gate 1 | 记录/测力、严格判定、第三任务校准、请求空间、教师学生接口 | 无恒定力/虚假通过；范围和校准可信 |
| 第 3 周 | 合成器初版、五方法入口、请求与成本台账、首批数据 | 方法差异和重试预算可审查 |
| 第 4 周 Gate 2 | E0、动作回放、小样本学习、金标、正式协议与预算 | 通过可用性检查，冻结 E1—E4 与数据划分 |
| 第 5—6 周 Gate 3 | 上游正式比较、核心消融、数据卡与 D1/D2 质量 | 能说明相对强基线的真实增量与失败 |
| 第 7—10 周 Gate 4 | 固定 VLA 的两类数据比较、多训练种子、闭环评估 | 不混入新训练变量；不使用测试选模 |
| 第 11—12 周 Gate 5 | 必要泛化复核、成本与覆盖总结、封版和第三方复算 | 逐项签收 R1—R8，未支持结论明确保留 |

关键路径：可信执行和评价 → 合成方法与强基线 → 回放及小数据学习 → 正式生产与比较 → 固定学生验证。D 从第 1 周参与，不等待 C 全部完成。若质量关口延期，正式运行顺延；不通过删掉审计或强基线补进度。

## 16 资源管理与暂停条件

Gate 0 报告环境执行、候选生成、录制存储的中位数/P90 和并发；Gate 2 增加新数据合格率、重复率、每条有效数据成本、训练吞吐及完整闭环评估成本。API 模型版本、缓存、温度和调用上限固定，敏感凭据不写入交付文件。

预算包括开发、校准、全部失败/重试、去重、标注、正式采集、18 次计划训练及评估，不能只用成功回合耗时估算。仿真资源按候选实际执行步数估算；存储包括未接受轨迹。建议单列约 25% 返工缓冲，最终由负责人结合设备批准。

出现以下情况暂停扩量：力或时间轴不可信；请求约束被静默修改；阶段标签与物体事件系统性不符；学生不能回放教师动作；正式测试信息进入生成或训练；成本台账不能覆盖内部尝试。

资源不足时的取舍顺序：先取消额外模型结构、在线感知开发、复杂恢复、第二学生骨干和大规模曲线；保留可信测量、G2/G3 强基线、完整台账、必要接触任务以及最小充分的学生证据。若仍不足，预先缩小声明范围与正式规模，不事后删结果。

## 17 风险与应对

| 风险 | 识别信号 | 处理 |
|---|---|---|
| 只是多试几次 | 同候选/资源预算下优势消失 | 将收益归因于采样预算，不强称方法优势 |
| 只是筛选更严格 | 发布质量高，但产率和覆盖极低 | 同筛选强基线，报告拒绝与缺覆盖 |
| 只覆盖容易请求 | 大量缺失困难阶段或对象 | 生成前冻结配额，未完成进入分母 |
| 规则已足够 | G3 在成本和质量上均不劣 | 如实报告，重新界定方法增量 |
| 重复数据充数 | 改写语言或切更多窗口后数量暴增 | 按 lineage 与实际物理行为去重，报告独立初态 |
| 上游与学生混淆 | 教师用隐藏力通道，学生无对应接口 | 回放优先，统一接口或收缩目标 |
| 物理常识过度归因 | 教师直接读真值，却称模型从视觉推断 | 分开报告特权合成与学生部署设定 |
| 数据反复拟合测试 | 最终审计反馈进入重采样 | 隔离封存集，变更后另行评测 |
| 验证器自证 | 只报告生成器自己的通过标记 | 独立校准、封存请求、接受/拒绝抽查 |
| 无学习增益 | 教师质量高，学生各对照无差异 | 检查可表达性、分布和预算，报告证据边界 |

## 19 启动时直接下达的任务

给 A：先交可信执行与测力，不扩大复杂控制器；第一周与 D 确认哪些教师动作学生能表达，第二周交第三任务校准和恢复初态证据。

给 B：先冻结物理判定、计数和审计边界；把生成期通过与最终合格分开；正式比较优先卡住 G2/G3、成本和缺覆盖，不允许只报成功数据质量。

给 C：第二周交请求空间和具体算法规格；第三至四周交合成器、五方法统一入口和预算执行；不是再造一个全面在线智能控制系统。

给 D：第一周对齐动作，第三至四周交回放与小数据学习；统一数据导出和去重；正式比较只换数据来源，不自行加入新损失制造混杂。

负责人在 Gate 0 批准角色、最低任务范围和开发预算，在 Gate 2 批准正式矩阵、样本量、18 次训练是否具备资源、阈值、测试封存与最终排期。所有未确定项都在关口前解决，不由执行成员在正式结果出来后自由调整。
